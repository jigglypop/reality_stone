# 교전 규칙(8팩션 체스형) 정리: `experiments/lbigd/envs/combat.py`

본 문서는 `GridCombatEnv`의 현재 규칙을 “참고용 고정본”으로 정리한다.

## 1. 구성 요소

### 1.1 보드
- 정사각 격자 보드: `board_size x board_size`
- 좌표: `(x, y)`이며 `0 <= x,y < board_size`

### 1.2 팩션과 말(유닛)
- 팩션 수: `n_factions`
- 팩션 f의 말 수: `p{f}_units`
- 말은 “유닛”이며, 유닛 인덱스는 `i`

### 1.3 스폰
- `spawn_mode="zones"`: 팩션별 구역에 배치하되, 구역 수용이 안 되면 자동으로 `global`로 전환
- `spawn_mode="global"`: 전체 보드에서 중복 없이 전 팩션 말들을 랜덤 배치
- 보드 용량(`board_size^2`)보다 총 말 수가 크면 에러

## 2. 행마(이동/캡처) 규칙

행마는 유닛별로 “패턴”을 가진다. 패턴은 `normal`, `cannon`, `knight` 3종으로 구성된다.

### 2.1 방향 집합
- 직선 4방향: 상/하/좌/우
- 대각선 4방향: 좌상/우하/좌하/우상
- `dir_count`는 위 방향 목록의 앞에서부터 `dir_count`개를 사용한다.
- `cannon`은 직선 4방향만 사용한다.

### 2.2 공통 파라미터
- `dir_count`: 사용할 방향 개수
- `max_range`: 한 방향으로 진행 가능한 최대 거리

### 2.3 normal (슬라이딩)
- 한 방향으로 1칸씩 진행하며 최대 `max_range`까지 본다.
- 빈칸은 이동 가능.
- 진행 중 처음 만나는 말이 적이면 그 칸으로 캡처 가능.
- 진행 중 처음 만나는 말이 아군이면 그 방향은 즉시 종료.
- 말 위로 뛰어넘을 수 없다.

### 2.4 cannon (포: 스크린 1개 점프 캡처)
- 직선 방향에서만 동작한다.
- 스크린 이전:
  - 빈칸은 이동 가능.
  - 처음 만나는 말은 “스크린”이 된다(그 칸으로는 이동/캡처하지 않음).
- 스크린 이후:
  - 빈칸은 통과(이동 불가, 캡처 타겟 탐색만 계속).
  - 처음 만나는 말이 적이면 그 칸으로 캡처 가능 후 종료.
  - 처음 만나는 말이 아군이면 종료.
- 스크린이 없으면 포는 캡처할 수 없다.

### 2.5 knight (마: 고정 오프셋 점프)
- (±2,±1), (±1,±2) 8개 오프셋을 사용한다.
- 중간 칸의 점유 여부와 무관하게 착지 가능(점프).
- 착지칸이 빈칸이면 이동, 적이면 캡처, 아군이면 불가.
- `dir_count/max_range`는 의미가 없다(고정 패턴).

## 3. 턴 진행
- 한 턴에서 현재 팩션의 살아있는 모든 유닛에 대해 “가능한 모든 행동(이동/캡처)”을 생성한다.
- 가능한 행동들 중에서 랜덤으로 1개를 고른다.
- 시작 팩션은 매 게임 번갈아가며 선택하고(`start_mode="rotate"`), 이후 팩션 순서는 순환한다.

## 3.1 지형 장애물(선택)
- `obstacles`: 장애물 좌표 목록(칸 단위)
- 또는 `obstacle_mode` + `n_obstacles`로 생성
  - `obstacle_mode="zones"`: 팩션 구역별로 균등 분배
  - `obstacle_mode="random"`: 전체 보드에서 랜덤
- 장애물은 스폰되지 않으며, 이동/캡처 대상이 될 수 없고, 슬라이딩/포 탐색에서 진행을 막는다.

## 4. 승리/종료 조건

### 4.1 체스형(`game_mode="normal"`)
- 킹은 각 팩션의 유닛 인덱스 0으로 간주한다.
- 상대 킹을 캡처하는 순간, 캡처한 팩션이 즉시 승리하며 게임 종료.
- `max_steps` 타임아웃이면, 남은 말 수가 가장 많은 팩션이 승리.

### 4.2 (보조) 역체스(`game_mode="reverse"`)
- 어떤 팩션의 말 수가 0이 되는 순간, 그 팩션이 즉시 승리하며 게임 종료.
- `max_steps` 타임아웃이면, “남은 말 비율(현재/초기)”이 가장 낮은 팩션이 승리.

## 5. 패턴 생성/배정(초기화)
- 각 팩션은 `cannon_ratio`, `knight_ratio`를 가진다.
- 각 유닛은 `unit_key`(0~1 균등 난수)로 타입이 배정된다.
  - `unit_key < knight_ratio`면 `knight`
  - 그렇지 않고 `unit_key < knight_ratio + cannon_ratio`면 `cannon`
  - 나머지는 `normal`
- `dir_count/max_range`는 유닛별로 생성되며, 팩션 말 수 비율에 따라 평균이 달라진다.

## 6. 밸런싱(승률 평준화) 루프
- `simulate(n_games, n_rounds, lr)`는 라운드마다 `n_games` self-play를 돌려 승률을 측정한다.
- 목표 승률은 `1/n_factions`.
- 라운드마다 팩션별 오차에 따라 유닛별 `dir_count/max_range`를 연속값으로 갱신한다.
- 동일 오차로 `cannon_ratio/knight_ratio`도 갱신한 뒤, 타입을 재배정한다.

## 7. 출력(리포트)
- `patterns`: 팩션별 유닛 패턴 목록
  - `("normal", dir_count, max_range)`
  - `("cannon", dir_count, max_range)`
  - `("knight", 8, 1)`
